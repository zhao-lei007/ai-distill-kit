# ai-distill-kit：用 AI 蒸馏自己

> 把你和 AI 助手对话里「手打的判断」，每周提炼成一份可复用的岗位知识库。
> 两层目录承载，机器做筛选，人只做四个决策。

这是视频《用 AI 蒸馏自己》配套的落地方案。你不需要会写代码，把本仓库的 `SKILL.md` 交给你自己的 AI 助手，它会在你电脑上把整套结构搭起来，并完成第一次蒸馏。

---

## 一、你需要先有什么

1. **至少一个正在用的项目文件夹**：里面有 `.git`、`AGENTS.md`（或 `CLAUDE.md`）、`project.md`、`changelog.md`。这是上一期《零帧起步，指挥 AI 干活》的四件套。没有的话先看上一期。
2. **一个能读本地文件、能执行命令的 AI 助手**。本方案主要面向：
   - OpenAI Codex（CLI / 桌面版 / IDE 插件）
   - DeepSeek Harness（dsh）
   - 腾讯 WorkBuddy
   - Claude Code（顺带兼容）
3. **每次开工都在项目文件夹里启动对话**。会话记录是按路径存的，路径就是项目的身份证；没有这条，后面所有按项目提取的步骤都会退化成全库盲扫。

---

## 二、三步用起来

### 第 1 步：把技能装进你的助手

三种方式任选其一，效果一样：

| 方式 | 怎么做 | 适合谁 |
|---|---|---|
| A. 直接粘贴 | 打开本仓库的 `SKILL.md`，全选复制，粘贴到对话框发送 | 所有工具，最不容易出错 |
| B. 装成技能 | 把 `ai-distill-kit/` 整个文件夹放进下表的技能目录，重启助手 | 想长期复用 |
| C. 让助手自己装 | 对助手说「把这个仓库克隆到你的技能目录里」并给出仓库地址 | 助手能联网克隆时 |

技能目录（放整个文件夹，保留里面的 `SKILL.md`）：

| 工具 | 个人级技能目录 | 项目级技能目录 |
|---|---|---|
| Codex | `~/.codex/skills/` | `<项目>/.codex/skills/` |
| DeepSeek Harness | `~/.agents/skills/` | `<项目>/.agents/skills/` |
| WorkBuddy | `~/.workbuddy/skills/` | `<项目>/.workbuddy/skills/` |
| Claude Code | `~/.claude/skills/` | `<项目>/.claude/skills/` |

大陆网络下 GitHub 的 raw 直链经常打不开，但仓库页面一般可以。所以方式 A 最稳：页面上能看到的内容就是全部，不依赖下载。

### 第 2 步：在项目文件夹里启动助手，说一句话

```
按 ai-distill-kit 的方案，帮我盘点电脑上的项目文件夹，搭一层岗位目录，然后做第一次知识蒸馏。
```

助手会按 `SKILL.md` 里的七个阶段走：确认环境 → 盘点项目 → 定岗位目录 → 搭骨架 → 接线 → 首轮考古 → 设每周例行。每一步涉及移动文件都会先问你。

### 第 3 步：每周一花十分钟

助手会给你一条固定的每周提示词。你只需要看它产出的周报，做四件事：宣布哪些知识失效、裁决冲突、定优先级、补充机器读不到的背景。

## 三、这套结构长什么样

```
我的岗位/                          ← 岗位目录：外接大脑
  AGENTS.md                        ← 入口：知识路由 + 通用规矩
  业务知识/
    <分类A>.md                     ← 正式知识，每条一个三级标题
    <分类B>.md
    _候选/
      观察池.md                    ← 只出现过一次的判断，56 天内复现才晋升
      weekly-YYYYMMDD/             ← 每周蒸馏报告
    CHANGELOG.md                   ← 每次合并动了什么
    _迁移记录.md                   ← 项目挪过位置时的旧→新路径对照（可选）
  项目A-某报表补口径/               ← 项目目录：一件具体的活
    .git/
    AGENTS.md                      ← 项目规矩，末尾加一段引用上级知识
    project.md
    changelog.md
  项目B-某功能验收/
```

两层各管什么：

| | 项目目录 | 岗位目录 |
|---|---|---|
| 承接什么 | 一件具体的活的对话、上下文、产物 | 跨项目复用的判断、口径、踩坑 |
| 谁写 | 你和助手在干活时写 | 每周蒸馏时由助手写，你审 |
| 生命周期 | 活结束就归档 | 跟着岗位走，长期保鲜 |
| 助手怎么读 | 启动时自动读 | 项目 AGENTS.md 里显式指过去，按任务类型只读对应条目 |

**为什么项目层要显式引用上级**：Codex 和 dsh 读规矩文件的范围都是「从 Git 根目录往下到当前目录」，不会往 Git 根之上找。岗位目录在 Git 根之上，所以不写这一句它就看不见。

## 四、蒸馏的五步流水线

| 步骤 | 做什么 | 关键规则 |
|---|---|---|
| 1 捞 | 从助手的会话记录里取出你的消息 | 只取**手打**的：排除超长的、带多级标题的、以「# 任务」开头的编排指令。防回音室 |
| 2 筛 | 判断每条是配置信息还是可迁移知识 | 判据是**可迁移性**：换个项目还成立的才是知识。含具体 ID 又含规则的，泛化后保留，置信度封顶 medium |
| 3 存 | 写入正式文件或观察池 | 高置信直接入正式；中低置信入观察池；已有条目复现则更新「最近确认」 |
| 4 保鲜 | 处理过期与冲突 | 观察池 56 天不复现自动过期；正式条目 90 天未确认标「待复核」；**机器只能标待复核，只有人能标失效**；失效不删，移到文件末尾编号不变 |
| 5 回灌 | 让助手下次干活时用上 | 岗位 AGENTS.md 写路由：按任务类型读哪个文件；项目 AGENTS.md 指向上级 |

判读提示词、置信度分流、八种合并动作，见 `prompts/weekly-distill.md`。

## 五、护栏

助手执行本方案时必须遵守（已写进 `SKILL.md`）：

- 不上传任何对话内容到外部服务，全部在本机完成。
- 凭据、令牌、密码、内网地址一律脱敏后再写入知识文件。
- 不移动、不删除任何已有文件，除非你在对话里明确同意；移动项目文件夹前先完成一次考古提取并登记路径对照。
- 只在已有 AGENTS.md 末尾**追加**引用段落，不改写原有内容。
- 不碰 `.git/` 目录。

## 六、工具差异与兜底

各工具会话记录在哪、规矩文件怎么读、读不到时怎么办，见 `tools/README.md`。

一句话版：Codex 和 dsh 的会话记录在本机可读，能直接按项目路径过滤；WorkBuddy 的会话记录路径官方未公开，走兜底方案，即在项目 AGENTS.md 里要求助手在每次会话结束前，把你手打的业务判断原话追加到项目内的候选文件，每周蒸馏时从候选文件读。

## 七、仓库内容

```
ai-distill-kit/
  README.md                       ← 本文，给人看
  SKILL.md                        ← 给助手执行的完整步骤
  prompts/
    weekly-distill.md             ← 每周判读提示词（收/丢口径、置信度、合并动作）
  templates/
    岗位-AGENTS.md                 ← 岗位目录入口文件模板
    项目-AGENTS-追加段.md           ← 追加到项目 AGENTS.md 末尾的引用段
    业务知识-分类文件.md            ← 正式知识文件与条目格式
    观察池.md
    CHANGELOG.md
    weekly-report.md              ← 每周报告格式
  tools/
    README.md                     ← 四个工具的会话路径、规矩文件、技能目录、兜底
    extract_codex.py              ← Codex 会话提取脚本（已在真实数据上验证）
```
