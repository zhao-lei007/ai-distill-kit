# 岗位目录说明

这是「<岗位名>」的岗位目录，下面每个子文件夹是一件具体的活（项目）。本文件是知识库的入口。

## 知识路由

干活前先按任务类型读对应文件，只读相关条目，不要一次全读：

- 涉及 <分类1> 的任务 → 读 `业务知识/<分类1>.md`
- 涉及 <分类2> 的任务 → 读 `业务知识/<分类2>.md`
- 拿不准归哪类 → 先看各文件的三级标题列表，标题就是一句话知识

标了「待复核」「阶段性」的条目可以参考，但要提醒我它的状态。标了「已失效」的条目不要用。

## 通用规矩

- 发现知识文件与现场事实不符：先告诉我，不要自行修改知识文件。
- 我在对话里手打的业务判断，如果和知识文件不一致，以我这次说的为准，并提醒我知识文件可能要更新。
- 密码、令牌、内网地址不写进任何知识文件。

## 每周例行

```

```
